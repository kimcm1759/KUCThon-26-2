# Claude Code 음향 효과 제작·정리 지침

> 이 문서를 Claude Code 프로젝트에 넣고, 참고 페이지나 효과음 파일을 전달할 때 작업 기준으로 사용합니다.

## 1. 목표와 범위

사용자는 원하는 소리를 자연어로 설명하거나 별도 음원 파일을 제공한다. Claude Code는 설명을 바탕으로 도구별 사운드를 프로젝트 안에서 새로 합성하고, 제공받은 음원은 파일과 메타데이터로 정리한다. 앱은 파손 도구와 사용자 입력에 맞는 사운드를 선택해 재생한다.

초기에는 **머신러닝 모델을 학습시키지 않는다.** 도구·동작·사운드 레이어가 구조화된 카탈로그를 만들고, 규칙 기반으로 적절한 소리를 조합한다. 이 카탈로그는 나중에 추천 또는 모델 학습 자료로 확장할 수 있다.

## 2. 참고 페이지와 오디오 취급

- 참고 페이지: https://hong-iron.github.io/SMASH-KU/
- 공개 저장소: https://github.com/Hong-Iron/SMASH-KU
- 저장소 README는 소리 파일이 없고 Web Audio로 합성한다고 설명한다. 따라서 Claude Code는 페이지에서 다운로드할 원본 오디오 파일이 있다고 가정하지 않는다.
- 페이지의 소리는 도구별 타이밍·역할·전반적인 느낌을 참고한다. 페이지의 오디오를 녹음·추출하거나 코드·파형을 복사하지 않는다.
- 참고 페이지를 바탕으로 작업할 때는 프로젝트 안에서 Web Audio API 또는 프로젝트의 기존 오디오 기술을 사용해 **독자적인 합성 효과음**을 만든다.
- 사용자가 별도 음원 파일을 제공하면 원본을 보존하며 카탈로그에 등록한다.
- 사용자는 출처 기록을 요구하지 않았다. 카탈로그에 출처·저작자 필드를 필수로 두지 않는다.

## 3. 역할 분담

### 사용자가 맡는 일

- 원하는 소리를 자연어로 설명한다. 예: “유압 프레스가 내려오며 낮게 웅 하고, 물체가 눌릴 때 금속이 짧게 찌그러지는 느낌.”
- 또는 음원 파일을 제공하고 어떤 도구·동작을 표현하는지 설명한다.
- 세기, 길이, 분위기, 선호하는 스타일을 알면 덧붙인다.

### Claude Code가 맡는 일

- 프로젝트 구조와 현재 오디오 구현을 먼저 확인한다.
- 참고 페이지의 도구별 동작을 살펴보고 필요한 레이어를 정리한다.
- 다운로드 가능한 원본 사운드가 없으면 오리지널 합성 효과음을 구현한다.
- 사용자가 제공한 음원은 파일 경로와 설명을 확인하고, 적절한 태그로 카탈로그에 등록한다.
- 모르는 특성을 실제 청취·측정한 것처럼 쓰지 않는다.
- 제공 원본 파일을 덮어쓰거나 삭제하지 않는다.
- 기존 도구 사운드가 부족하면 현황을 확인해 사용자에게 필요한 음원 또는 합성 레이어를 요청한다.

## 4. 우선 지원 도구와 필요한 소리

물건 재질이 아니라 파손 도구·효과가 기본 분류 기준이다. 앱은 가상 파손 효과만 제공하며 실제 위험 행동을 유도하거나 녹음을 요구하지 않는다.

| `tool_code` | 표시명 | `activation` 준비·시작 | `main_action` 핵심 동작 | `impact_detail` 세부 레이어 | `finish` 종료·잔향 |
|---|---|---|---|---|---|
| `hydraulic_press` | 유압 프레스 | 모터·유압 작동, 압력 상승 | 프레스가 내려오는 저음·압축음 | 삐걱임, 재질별 찌그러짐·균열 | 기계 멈춤, 압력 해제, 짧은 잔향 |
| `hammer` | 망치 | 휘두르는 짧은 공기음 | 가벼운/강한 타격 | 균열, 조각 튐, 타격 재질 공명 | 파편 낙하, 충격 잔향 |
| `aluminum_bat` | 알루미늄 배트 | 배트 스윙·공기 가르기 | 타격과 둔탁한 충격 | 속 빈 금속 울림, 떨림, 파편 | 금속 떨림 감쇠, 잔향 |
| `laser` | 레이저 | 충전·조준음 | 발사·지속 빔 | 지지는 소리, 절단, 에너지 충격 | 빔 종료, 전원 감쇠 |
| `bomb` | 폭탄 | 퓨즈·점화·긴장 상승 | 폭발과 저음 충격파 | 파편·잔해·공기 이동 | 폭발 잔향과 잔해 낙하 |

각 도구에 네 레이어를 모두 제공하는 것이 목표지만, 하나의 합성 레이어가 여러 역할을 충족할 수 있다. 레이어가 아직 없으면 카탈로그와 준비 현황에 빠진 상태를 표시한다.

## 5. 사용자 입력 예시

정해진 형식은 필수가 아니다. 예시:

```text
유압 프레스 소리를 만들어줘. 내려올 때는 낮은 모터음이 점점 커지고, 눌리는 순간 짧은 금속 찌그러짐이 나고, 끝에는 기계가 멈추는 느낌이면 좋겠어.
```

파일을 제공할 때:

```text
파일: sounds/incoming/metal_hit.wav
설명: 알루미늄 배트가 물체를 세게 때리는 소리. 짧고 속 빈 금속 울림이 남아.
도구: 알루미늄 배트
```

## 6. 태그 어휘

### 도구 코드

`hydraulic_press`, `hammer`, `aluminum_bat`, `laser`, `bomb`

### 소리 역할 (`sound_role`)

- `activation`: 준비, 충전, 휘두름, 기계 작동 시작
- `main_action`: 타격, 압축, 발사, 폭발 등 주요 동작
- `impact_detail`: 균열, 금속 공명, 파편, 지짐 등 세부 음향
- `finish`: 멈춤, 해제, 파편 낙하, 잔향 등 종료

### 동작 (`action`)

`tap`, `impact`, `press`, `swing`, `scrape`, `crack`, `break`, `rattle`, `charge`, `fire`, `beam`, `explosion`, `debris`, `decay`, `other`

### 강도 (`intensity`)

`light`, `medium`, `strong`, `unknown`

### 질감 (`texture_tags`)

`bright`, `dull`, `resonant`, `dry`, `crunchy`, `rattly`, `soft`, `sharp`, `low`, `metallic`, `airy`, `electronic`, `unknown`

### 재질 (`material_codes`, 선택 태그)

재질은 보조 정보다. 명확한 경우에만 `paper`, `cardboard`, `wood`, `steel`, `aluminum`, `glass`, `ceramic`, `plastic`, `unknown` 중 하나 이상을 쓴다.

## 7. Claude Code 처리 절차

### A. 참고 페이지를 기준으로 새 소리 만들기

1. 페이지와 저장소 README에서 도구 동작과 소리 역할을 확인한다.
2. 원본 음원 파일이 없다는 점을 고려해 오디오를 웹 페이지에서 추출하지 않는다.
3. 프로젝트의 프레임워크, 오디오 엔진, 디렉터리 구조, 기존 효과음 구현을 확인한다.
4. 각 도구의 네 레이어를 Web Audio API 또는 프로젝트의 기존 기술로 독립 구현한다.
5. 음높이, 노이즈, 필터, 엔벨로프, 레이어, 잔향 등을 조합해 오리지널 합성음을 만든다.
6. 레이어별로 켜고 끌 수 있도록 구성해 튜닝과 재사용이 가능하게 한다.
7. 기존 앱에서 재생할 수 있도록 파일 에셋 또는 생성 코드 형태로 저장하고 카탈로그를 갱신한다.
8. 요청받은 작업 범위 안에서만 수정하고 새 파일과 미구현 항목을 보고한다.

### B. 사용자가 음원 파일을 제공했을 때

1. 지정 파일이 실제로 있는지 확인한다. 접근 불가 파일을 등록된 것처럼 기록하지 않는다.
2. 파일명은 고유 ID 규칙으로 정리하되 원래 이름도 메타데이터에 보존한다.
3. 가능하면 재생 시간·포맷·샘플레이트·채널을 읽는다. 확인 불가능한 값은 `null`로 둔다.
4. 자연어에서 도구, 역할, 동작, 강도, 질감 태그를 추출한다.
5. 설명에 없는 내용을 추측하지 않는다. 불확실하면 `unknown`으로 남긴다.
6. 원본을 보존하고, 변환이 필요하면 별도 파생 파일을 만든다.
7. 카탈로그 JSON과 사람이 읽는 표를 함께 갱신한다.
8. JSON 파싱, 경로 존재, ID 중복을 확인하고 추가 결과를 요약한다.

## 8. 파일 이름과 디렉터리

프로젝트에 기존 규칙이 있으면 이를 우선한다. 없다면 다음을 사용한다.

```text
sounds/
  catalog.json
  README.md
assets/
  audio/
    tools/
      hydraulic_press/
      hammer/
      aluminum_bat/
      laser/
      bomb/
    provided/
```

파일 ID 형식:

```text
{tool_code}_{sound_role}_{NNN}
```

예: `hydraulic_press_main_action_001`, `laser_activation_001`.

## 9. 카탈로그 스키마

`sounds/catalog.json`에 아래 구조를 사용한다. 실제 파일 경로에는 공백을 넣지 않는다.

```json
{
  "schema_version": 1,
  "sounds": [
    {
      "sound_id": "hydraulic_press_main_action_001",
      "file_path": "assets/audio/tools/hydraulic_press/main_action_001.wav",
      "original_filename": null,
      "source_type": "generated_in_project",
      "tool_code": "hydraulic_press",
      "sound_role": "main_action",
      "target_objects": [],
      "material_codes": ["aluminum"],
      "action": "press",
      "secondary_actions": ["crush"],
      "intensity": "strong",
      "texture_tags": ["low", "metallic", "crunchy"],
      "description": "프레스가 내려오며 물체를 압축하는 오리지널 합성 효과음.",
      "duration_seconds": null,
      "sample_rate_hz": null,
      "channels": null,
      "created_at": "YYYY-MM-DD",
      "notes": "프로젝트 내 합성. 참조 페이지의 오디오 파일을 사용하지 않음."
    }
  ]
}
```

필드 규칙:

- `sound_id`: 고유한 snake_case ID.
- `file_path`: 프로젝트 루트 기준 상대 경로. 생성 코드만 있는 경우 코드/모듈 경로를 기록한다.
- `original_filename`: 사용자가 준 원본 이름. 합성음이면 `null`.
- `source_type`: `generated_in_project` 또는 `provided_audio`.
- `tool_code`: 위 5개 도구 코드 중 하나.
- `sound_role`: 네 가지 레이어 역할 중 하나.
- `target_objects`: 적용 가능한 물건 코드. 명확하지 않으면 빈 배열.
- `material_codes`: 보조 재질 태그. 모르면 `["unknown"]`.
- `action`, `secondary_actions`, `intensity`, `texture_tags`: 위 태그 어휘를 사용한다.
- `description`: 사용자가 설명했거나 실제 구현한 음향을 요약한다.
- 파일 속성은 확인 가능할 때만 입력하고, 아니면 `null`.
- `created_at`: 실제 생성 날짜.

## 10. 소리 선택과 조합 규칙

1. 도구 코드와 사운드 역할이 일치하는 소리를 우선 선택한다.
2. 사용자 입력 강도에 따라 `intensity`가 맞는 레이어를 선택하거나 합성 강도를 조정한다.
3. `activation → main_action → impact_detail → finish` 순서로 재생하되, 도구 동작에 맞게 겹침·간격을 설정한다.
4. 사용자의 탭·누르기·쓸기 입력과 타격·압축·빔 동작을 연결한다.
5. 재질 태그는 세부 레이어를 고르는 보조 기준으로만 사용한다.
6. 필요한 레이어가 없으면 엉뚱한 도구의 음향을 대신 쓰지 않는다. 일반 폴백을 쓰거나 부족 항목을 사용자에게 요청한다.
7. 반복 피로를 줄이기 위해 가능한 경우 변형을 여러 개 만들거나 합성 파라미터를 조금씩 바꾼다.

## 11. 필요한 소리 현황과 사용자 요청

Claude Code는 기존 카탈로그와 구현을 확인해 도구별 네 역할의 상태를 관리한다.

- `covered`: 구현·등록되어 앱에서 사용할 수 있음
- `missing`: 구현 또는 음원이 없음
- `needs_review`: 태그·재생 적합성 점검이 필요함

사용자가 “필요한 소리 뭐가 남았어?” 또는 “음원을 요청해줘”라고 하면:

1. 다섯 도구 각각의 네 역할을 검사한다.
2. `missing`과 `needs_review`를 구분한다.
3. 사용자가 음원을 제공해야 하는 항목인지, Claude Code가 합성 구현하면 되는 항목인지 구분한다.
4. 빠진 항목만 도구별로 묶어서 요청한다. 이미 등록된 소리는 다시 요청하지 않는다.
5. 사용자가 파일을 제공할 경우 파일과 자연어 설명을 요청한다.
6. 사용자가 직접 파일을 찾지 않아도 되는 합성음 작업은 Claude Code가 구현 가능한 범위를 제시한다.

요청 예시:

```text
아직 준비가 필요한 소리:
- 유압 프레스: 압력 해제음 (합성 구현 가능)
- 망치: 파편 낙하 레이어 (합성 구현 가능)
- 알루미늄 배트: 금속 떨림 변형 샘플 (직접 제공하면 카탈로그에 추가)
- 레이저: 지속 빔음 (합성 구현 가능)
- 폭탄: 잔해 낙하음 (음원 제공 또는 합성 중 선택)

파일을 보내실 경우 파일과 함께 “어떤 도구의 어떤 동작 소리인지” 자연어로 적어주세요.
```

## 12. Claude Code 작업 지시 템플릿

### 참고 페이지를 바탕으로 새 효과음 구현

```text
https://hong-iron.github.io/SMASH-KU/ 를 도구 동작과 사운드 연출의 참고로 확인해줘.
저장소 README에 따르면 사운드 파일 없이 Web Audio로 합성하므로 다운로드나 녹음 추출을 시도하지 마.
기존 프로젝트의 오디오 방식과 폴더 구조를 먼저 살펴보고, 이 프로젝트만의 오리지널 효과음을 구현해줘.
도구 코드는 hydraulic_press, hammer, aluminum_bat, laser, bomb를 사용하고,
각 도구의 activation, main_action, impact_detail, finish 레이어를 구성해.
생성한 오디오 파일 또는 합성 코드를 프로젝트에 저장하고 sounds/catalog.json과 sounds/README.md를 갱신해줘.
마지막에 구현된 레이어, 남은 레이어, 수정한 파일을 알려줘.
```

### 제공받은 음원 등록

```text
이 파일과 설명을 음향 카탈로그에 등록해줘.
설명: [자연어 설명]
도구/역할: [알고 있다면 기입]

이 문서의 규칙에 따라 파일을 확인하고 태그를 붙여 sounds/catalog.json과 sounds/README.md를 갱신해줘.
모르는 정보는 추측하지 말고 unknown으로 둬. 원본은 덮어쓰거나 삭제하지 마.
```

## 13. 완료 기준

- 다섯 도구와 네 가지 소리 역할별 현황이 관리된다.
- 참고 페이지에 원본 음원이 없으면 다운로드·녹음 추출을 시도하지 않고 오리지널 합성으로 처리한다.
- 프로젝트의 기존 오디오 구조와 기술을 확인한 뒤 필요한 파일만 수정한다.
- 합성 효과음은 역할별로 재사용·조절할 수 있게 구성한다.
- 카탈로그가 JSON으로 정상 파싱되고 경로와 ID가 유효하다.
- 제공된 음원 원본은 보존되고, 설명에 없는 정보는 추측하지 않는다.
- 부족한 소리가 있으면 사용자 제공 음원과 Claude Code 합성 구현 중 적절한 요청을 한다.
